## 1. プロダクト概要

- **名称**: **山網（Sanmou）**
- **目的**: 限られた人手で広い山林を把握・管理できるよう、地点の変化と受信状況を集約し、巡回・現地確認を支援する。倒木・土砂災害の予測や安全保証とは区別する。
- **主利用者**: 林業従事者、森林組合・林業事業体の管理担当者、山林所有者。自治体・防災等への展開は、対象業務と必要精度を別途検証する。
- **将来目標**: 一人で数百〜数千ノードの情報を把握する。通信容量、PC性能、認知負荷、設置・保守、人員削減効果は未実証。
- **基本UI**: PCの地図（`/map`）、詳細（`/sensors/[id]`）、ダッシュボード（`/dashboard`）、台帳（`/sensors`）、スマホWeb画面（`/mobile`）。正式な地図とデモ図形を区別する。
- **技術構成**: Next.js 16.4 (App Router / TypeScript) + FastAPI (Python 3.11)。
- **プラットフォーム方針 [確定]**:
  1. **Webファースト**: 現フェーズではWebブラウザでの操作・検証を最優先。ハードウェア未接続でもデモモードで完結検証可能。
  2. **Windows & macOS 両対応**: 双方を対象に設計し、実際に試したOS・版・起動方法を記録する。設計方針だけで動作保証しない。
  3. **完全オフライン自立動作 [最終目標]**: 電波の届かない山林現場でも、ローカルPC（SQLite + FastAPI + Next.js）単体で動作可能。外部SaaS・クラウド接続に依存しない。

## 2. 状態モデルとデータ境界

### 2.1 状態の独立管理（厳格分離）

- **観測重要度（Observation Severity）**: `normal` / `caution` / `danger` / `unknown`。試験用の変化検知と、実際の危険度を区別する。未校正・基準未設定を正常としない。
- **機器状態（Device Status）**: `online`（通信中）/ `offline`（通信断）/ `fault`（機器故障）/ `low_battery`（低電池）。観測重要度とは完全に独立して判定・表示する。
- **未判定（Unknown）**: 未観測のセンサーや登録直後のセンサーは、正常と推定せず「未判定」として保持する。

### 2.2 データソースの境界識別

1. `source: "demo"`: 開発・UI検証用の架空データ。画面上にも「デモデータ」を常時表示。
2. `source: "device_test"`: 実証実験スクリプト起動時、USBシリアル受信CSVや検証用SQLiteから読み出す実機生データ。
3. `source: "device"`: 本番永続化DBへ取り込まれた正規の観測データ。

## 4. 実装と要求の差

現在の基準共有はNext.jsのメモリAPIで、サーバー再起動後の永続性は未実装。スマホの未同期キューは設置情報であり、登録操作時刻に対応する機体履歴の選択とは別。
オフライン画面の初回起動・保持、ブラウザの保存失敗、利用者認証、未判定の一貫表示等も試験・改善対象。現在のコードの表示が要求と異なっていても、本書の改稿だけで解消したとはしない。
