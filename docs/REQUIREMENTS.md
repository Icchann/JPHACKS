# REQUIREMENTS.md — 山網（Sanmou）統合要件定義

> 文書版: 2.0 / 2026-10-24  
> 対象: JPHACKS / Next.js + FastAPI

---

## 1. プロダクト概要

- **名称**: **山網（Sanmou）**
- **目的**: 山林斜面の土壌水分・傾斜センサーを監視し、土砂災害や斜面崩壊の兆候を早期に検知・可視化する。
- **主利用者**: 自治体・森林管理者、現地調査・防災担当者、現場作業員。
- **基本UI**: PCブラウザ向け衛星地図をホーム（`/map`）とし、詳細（`/sensors/[id]`）、ダッシュボード（`/dashboard`）、台帳（`/sensors`）を提供。
- **技術構成**: Next.js 16.4 (App Router / TypeScript) + FastAPI (Python 3.11)。
- **プラットフォーム方針 [確定]**:
  1. **Webファースト**: 現フェーズではWebブラウザでの操作・検証を最優先。ハードウェア未接続でもデモモードで完結検証可能。
  2. **Windows & macOS 両対応**: 現場のWindows（COMポート / PowerShell）および開発用のmacOS（`/dev/tty.*` / POSIX）双方で最低限動作。
  3. **完全オフライン自立動作 [最終目標]**: 電波の届かない山林現場でも、ローカルPC（SQLite + FastAPI + Next.js）単体で動作可能。外部SaaS・クラウド接続に依存しない。

## 2. 状態モデルとデータ境界

### 2.1 状態の独立管理（厳格分離）
- **観測重要度（Observation Severity）**: `normal`（正常）/ `caution`（注意）/ `danger`（危険）。土壌水分量としきい値、傾斜角変化速度による自動判定。
- **機器状態（Device Status）**: `online`（通信中）/ `offline`（通信断）/ `fault`（機器故障）/ `low_battery`（低電池）。観測重要度とは完全に独立して判定・表示する。
- **未判定（Unknown）**: 未観測のセンサーや登録直後のセンサーは、正常と推定せず「未判定」として保持する。

### 2.2 データソースの境界識別
1. `source: "demo"`: 開発・UI検証用の架空データ。画面上にも「デモデータ」を常時表示。
2. `source: "device_test"`: 実証実験スクリプト起動時、USBシリアル受信CSVや検証用SQLiteから読み出す実機生データ。
3. `source: "device"`: 本番永続化DBへ取り込まれた正規の観測データ。

### 3.2 センサー・ハードウェア通信
| ID | 要件 | フェーズ |
|---|---|---|
| SNS-01 | 観測対象は土壌水分生値（`soil_raw`）、3軸加速度（`ax`, `ay`, `az`）、電池電圧（`battery_mv`） | MVP |
| SNS-02 | 通信経路はセンサー → LoRa集約機 → USBシリアル（115200bps・8N1）でPCへ入力 | MVP |
| SNS-03 | 入力レコード形式はヘッダーなし、CRLF区切りの `S0` 10フィールドパケット | MVP |
| SNS-04 | PC受信時にローカル受信日時を付与し、CSVへ安全に追記保存 | MVP |
| SNS-05 | マイコン起動ログ等の非S0行は除外し、破損行はカウントして握りつぶさない | MVP |
| SNS-06 | 最終受信から一定時間（例: 60分）途絶した端末を通信断（offline）と判定 | MVP |
| SNS-07 | 電池電圧の低下（30%以下相当）を低電池と判定 | MVP |
| SNS-08 | 加速度から傾斜角算出、土壌水分の校正、連続異常回数判定 | 後続（実機確定後） |
