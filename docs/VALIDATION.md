# VALIDATION.md — 検証範囲・核心体験・評価計画

更新日：2026-10-26

## 1. 根拠の区別

| 段階       | 記載できること                         | それだけでは示せないこと   |
| ---------- | -------------------------------------- | -------------------------- |
| 設計・要求 | 目標、想定利用者、実装したい機能       | 実装完了、実用性           |
| コード確認 | 対象コミットに処理が存在する           | 全経路が動く、現場で使える |
| 自動試験   | 対象条件・ケースでの成否               | 実機・無線・現地の成功     |
| 実機試験   | 機体・端末・環境を指定した動作         | 山全域の通信、危険の予測   |
| 業務実証   | 特定の利用者・業務での判断や負担の変化 | 他地域・全業務への一般化   |

運営AIによる文書評価は改善の手掛かりであり、上記の試験や競合優位性の証明には代用しない。

## 2. 現在確認できる記録

- ユーザーから、T1の受信ログ9行（seq=0〜8）が共有された。
- sample_msの差は1500〜1506 ms。PC到着遅延・長期の取得率は含まない。
- 3軸加速度を含み、土壌・電池は全行-1（未計測）。
- 最初の全軸ゼロは姿勢基準から除外する必要がある。
- 地図・グラフを表示した画面共有があるが、全機能の通し試験や現場効果を示すものではない。
- 基準共有・警告解除・NFC・端末内キュー等のコードを確認できる。今回の文書修正だけで実機試験済みとはしない。

過去のテスト成功報告を使用する場合も、その報告のコミットと実行条件を添える。最新コミットの成功へ読み替えない。

## 3. 実機デモで示す核心体験

T1を特定する → 受信を確認する → 基準を設定する → 安全な範囲で傾ける → T1の変化を見る → 警告を確認・解除する → 再試行する。

- 手動テスト警報と、実測データからの警報を区別する。
- デモ用角度・時間は設定値として表示し、倒木危険基準とは呼ばない。
- 全軸ゼロ・欠測・古いデータでは誤った基準登録や正常表示をしない。
- PC・スマホ間の共有、通信切断、消音後の再発条件、機体再起動を確認する。
- 10回程度の反復で、成功回数と基準取得・検知・表示・解除の時間を別々に記録する。回数は試験案で、実施済みではない。
- 動画にはコミット、端末、ID、実測／デモ、未計測項目、操作から反映までの時間を添える。
- 人を模擬樹木にする場合も無理な姿勢・転倒を避ける。実際の倒木・避難の実験ではない。

## 4. オフラインと同期の試験

外部回線を外し、スマホのモバイルデータも切った状態で、PCの受信・保存・閲覧を確認する。初回の依存導入・外部地図の有無も記録する。

スマホについては、PC接続中の利用、準備済み画面の圏外起動、未同期保存、再起動後の保持、帰還後の手動同期を分けて試す。localStorageがあるだけでオフライン起動を実現したとはしない。

保存領域が使えない場合、NFC非対応・権限拒否・読取失敗、GPS取得失敗、時計ずれ、重複送信、複数端末の競合、応答消失を確認する。機体ID選択・会場座標を実読取・実測と区別する。

登録操作時刻の履歴採用と現在値採用を分けて試す。操作後に機体を動かしてから同期する試験を行い、最新値への無断置換を防ぐ。履歴がなければ理由を示し、現在値登録を明示選択する。

## 5. 一人で数百〜数千ノードを扱うための段階評価

数は将来目標であり、表示できるピンの数だけでは達成としない。

1. **PC側負荷**：模擬データで数百・数千台の台帳、履歴、機体別最新値、検索、地図描画、API応答、メモリ、保存容量を測る。
2. **無線側容量**：同時送信、送信周期、中継、重複、欠測、再起動、法令上の使用条件を実機で評価する。PCへの模擬入力を無線実証としない。
3. **管理者の負担**：重要な変化・欠測を探す時間、確認候補の選択、警告件数、未確認の滞留を評価する。
4. **現場保守**：設置、交換、校正、電源、通信復旧に要する人時・移動・費用を含める。

目標応答時間・許容欠測・保守工数等の数値は、利用者の業務条件から設定する。現段階で適当に合格値を確定しない。

## 6. 業務上の有用性

初期候補は森林組合・林業事業体の巡回担当者と管理担当者。山林所有者の直接利用か委託先経由かも確認する。既存地図・巡回表・点検方法を調べ、試作あり／なしで同じ場面の判断を比較する。

記録するもの：

- 現在の確認頻度、移動・記録・判断の時間、担当範囲。
- どの樹木・林道沿いの地点を、なぜ継続観測したいか。
- 変化・欠測・情報の古さが確認候補に与える影響。
- 追加された設置・交換・確認の負担、誤警告、見落とし。
- 導入判断者、必要な精度・利用条件、運用費用。

現場協力先が確保できない場合は、模擬課題での操作試験と技術試験に限定し、「人員削減を実現」「課題解決を実証」と記載しない。

## 7. 海外・競合・通知の評価

海外の候補地域について、対象業務、既存サービス、使用周波数・認証、地図利用条件、電源、保守体制、言語を調べる。国内デモの成功を海外需要の証明にしない。

比較軸は、目的、設置条件、通信構成、インターネットの必要箇所、ローカル閲覧、費用・保守。Dryad等の一次資料を比較の入口とし、「追随不可能」と結論付けない。

ウェアラブル・近接SOSは別試験とし、到達性、携帯状態、画面・音・振動の認知、誤通知を評価する。危険作業中の試験や、実際の災害・救助を起こす試験は行わない。

## 8. 結果の記録様式

| 項目     | 記入する内容                                                             |
| -------- | ------------------------------------------------------------------------ |
| 対象     | コミット、実行日、担当、試験名                                           |
| 条件     | PC・OS・スマホ・ブラウザ、機体ID、ファームウェア、配線・電源、通信・地図 |
| 方法     | 操作、試験データ、回数、合否基準                                         |
| 結果     | 成功・失敗数、遅延・取得率等、未計測・欠測、ログ・動画                   |
| 限界     | 未試験の条件、現場への適用可否                                           |
| 次の判断 | 続行、条件変更、対象変更、見送り                                         |

性能・省人化・安全・電池寿命は、対応する結果がある範囲だけで記述する。失敗時は設置条件・送信周期・表示・対象業務を見直し、未確認を成功として扱わない。
