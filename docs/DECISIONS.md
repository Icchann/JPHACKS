### DEC-19：ローカルマップ表示と座標合わせ方式 — 固定工区グリッド投影＋相対区画スロット併用方式（2026-10-26、Issue #33対応）

オンライン実地図（衛星タイル・詳細航空写真）は「樹冠で見づらい・描画と通信が重い・ローカル環境で更新できない」ため、山網の標準ローカルマップでは以下の実事例を組み合わせた **「案C：固定工区グリッド投影＋相対区画スロット併用方式」** を採用する。

- **参考にした実事例**:
  1. **森林施業図・Avenza Maps・GARMIN Custom Maps（固定2点アンカー／固定BBox平面直交投影）**:
     下絵図面（または工区枠）の北西端 $(\text{maxLat}, \text{minLon})$ と南東端 $(\text{minLat}, \text{maxLon})$ を**工区（`Mountain`）単位の固定定数**として保持し、機体の緯度経度を正規化座標 $(u, v) \in [0, 1]^2$ へ線形投影する。**検索フィルタや機体の追加・削除によって `bounds` を再計算しない**ため、背景図とピン位置が絶対にズレない。
  2. **スマート林業（架線集材作業計画図）・国土交通省斜面防災点検図・トンネル/鉄道保線スケマティック図（基準点からの相対座標・林班区画スロット）**:
     山間部でのGPSマルチパス誤差や屋内デモ環境に対応するため、背景を「尾根・沢・林道・林班グリッド（100mメッシュ等）」の軽量ベクター模式図とし、工区固定枠外（または屋内会場座標）の機体は **「工区内の相対区画スロット（または集材基点からの相対オフセット）」** として固定区画内に整列表示し、「参考配置（工区外座標／未位置合わせ）」バッジを明示する。
- **デモ地物の分離**: 実機テストモード（`dataMode === "test"`）では架空のデモ用オーバーレイ（`DEMO_OVERLAY_PATHS` / `DEMO_OVERLAY_POINTS`）を座標計算および初期描画に混在させない。

### DEC-20：マップ操作とページスクロールの分離・凡例の外出し設計（2026-10-26）

- **スクロール分離（Cooperative Gesture 方式）**:
  - 通常表示時（`!isExpanded`）、地図上での単なる縦ホイール操作で `panOffset` を動かさず（地図とページスクロールの同時移動を防止）、地図の移動は **ドラッグ操作（マウス／タッチ）** で行う。
  - 地図のホイール拡大・縮小は **`Ctrl` / `⌘` + ホイール**（または全画面拡大表示時 `isExpanded` のホイール）に限定し、ネイティブの非 passive `wheel` リスナーで `preventDefault()` / `stopPropagation()` および CSS `overscroll-behavior: contain` を適用して親ページのスクロール連鎖を遮断する。
- **凡例（Legend）の非重なり配置**:
  - SVG キャンバス内部の右下／左下に直接描画していた `<g className={styles.mapLegend}>` は、地形・ピンと重なりズーム時に巨大化するため廃止する。
  - 凡例は SVG キャンバス外のツールバー（開閉トグル付きのコンパクト凡例バー）またはマップ下部フッターへ外出しし、地図の視認領域を100%確保する。

### DEC-21：Issue #27〜#36 対応の共通状態評価・永続化・セキュリティ設計（2026-10-26）

1. **実機未受信時の架空値排除と同期結果確認（Issue #27）**: `/mobile` で `dataMode === "test"` かつ対象ノードの観測レコードが未受信の場合は `latestObs = null` とし、架空の固定値（`-128, -112, 944` / `1420 ADC` / `3280 mV`）へのフォールバックや未受信時の基準確定を行わない。また `POST /api/test-baseline` の HTTP 応答を確認してから同期成否を表示する。
2. **画面横断での姿勢・状態評価ロジックの統一（Issue #28）**: 地図（`/map`）・管理台帳（`/sensors`）・詳細（`/sensors/[id]`）・スマホ（`/mobile`）で共通の評価関数を用い、台帳の `unknown`（未判定・未接続）を勝手に `normal` や `ok`（故障なし）へ変換しない。
3. **機体別基準・機体別警告ラッチのサーバー側管理（Issue #29）**: `/api/test-baseline`（およびバックエンド連携）において、警告状態を単一グローバル変数ではなく **機体コード別の辞書（`activeAlertsByNode: Record<string, AlertState>`）＋ローカルファイル永続化** として管理し、別機体（例：`S1`）の基準操作や新規タブ起動によって `T1` の警告が消えない設計とする。また全軸ゼロ `(0, 0, 0)` や不正ボディは `400 Bad Request` で拒否する。
4. **圏外登録キューの永続化成否検証（Issue #30）**: `localStorage.setItem` の成功を確認した後にのみ「端末内に保存しました」と通知し、容量超過・書込拒否時は「端末内保存に失敗しました（画面を閉じず再試行またはJSON控えを保存してください）」と明示する。
5. **観測API停止時の経過時間（Wall-Clock）による鮮度・通信途絶判定（Issue #31）**: ポーリング失敗時に固定される `testObservations.refreshed_at` ではなく、クライアント側の現在時刻時計（定期更新される `nowEpoch`）と `received_at` の差、および `useTestObservations().error`（API疎通エラー）を分離して評価し、API停止や60秒超過時に「オンライン・受信中」が凍結しないようにする。
6. **LAN共有時の操作保護トークン／PIN認可（Issue #32）**: 単独PC利用（`127.0.0.1` 待受）とスマホLAN共有（`0.0.0.0` 待受）を起動オプションで区別し、変更・削除系API（`/api/test-sensors`, `/api/test-observations` DELETE, `/api/test-baseline` POST/DELETE）には起動時に発行される現場操作パスコード（QRコードURLに付与またはヘッダー検証）を要求して同一LAN上の無認証第三者による破壊的操作を防ぐ。
7. **クロスプラットフォーム改行・CI整備（Issue #35）**: `backend/tests/test_csv_store.py` の BOM テストで `write_bytes` を用いて Windows 環境での `CRCRLF` 二重変換を防ぎ、GitHub Actions（Windows / Ubuntu / macOS）による自動テストワークフローを追加する。
