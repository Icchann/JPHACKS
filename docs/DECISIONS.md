### DEC-19：ローカルマップ表示と座標合わせ方式 — 固定工区グリッド投影＋相対区画スロット併用方式（2026-10-26、Issue #33対応）

オンライン実地図（衛星タイル・詳細航空写真）は「樹冠で見づらい・描画と通信が重い・ローカル環境で更新できない」ため、山網の標準ローカルマップでは以下の実事例を組み合わせた **「案C：固定工区グリッド投影＋相対区画スロット併用方式」** を採用する。

- **参考にした実事例**:
  1. **森林施業図・Avenza Maps・GARMIN Custom Maps（固定2点アンカー／固定BBox平面直交投影）**:
     下絵図面（または工区枠）の北西端 $(\text{maxLat}, \text{minLon})$ と南東端 $(\text{minLat}, \text{maxLon})$ を**工区（`Mountain`）単位の固定定数**として保持し、機体の緯度経度を正規化座標 $(u, v) \in [0, 1]^2$ へ線形投影する。**検索フィルタや機体の追加・削除によって `bounds` を再計算しない**ため、背景図とピン位置が絶対にズレない。
  2. **スマート林業（架線集材作業計画図）・国土交通省斜面防災点検図・トンネル/鉄道保線スケマティック図（基準点からの相対座標・林班区画スロット）**:
     山間部でのGPSマルチパス誤差や屋内デモ環境に対応するため、背景を「尾根・沢・林道・林班グリッド（100mメッシュ等）」の軽量ベクター模式図とし、工区固定枠外（または屋内会場座標）の機体は **「工区内の相対区画スロット（または集材基点からの相対オフセット）」** として固定区画内に整列表示し、「参考配置（工区外座標／未位置合わせ）」バッジを明示する。
- **デモ地物の分離**: 実機テストモード（`dataMode === "test"`）では架空のデモ用オーバーレイ（`DEMO_OVERLAY_PATHS` / `DEMO_OVERLAY_POINTS`）を座標計算および初期描画に混在させない。

### DEC-20：マップ操作とページスクロールの分離・凡例の外出し設計（2026-10-26）

- **スクロール分離（Cooperative Gesture 方式）**:
  - 通常表示時（`!isExpanded`）、地図上での単なる縦ホイール操作で `panOffset` を動かさず（地図とページスクロールの同時移動を防止）、地図の移動は **ドラッグ操作（マウス／タッチ）** で行う。
  - 地図のホイール拡大・縮小は **`Ctrl` / `⌘` + ホイール**（または全画面拡大表示時 `isExpanded` のホイール）に限定し、ネイティブの非 passive `wheel` リスナーで `preventDefault()` / `stopPropagation()` および CSS `overscroll-behavior: contain` を適用して親ページのスクロール連鎖を遮断する。
- **凡例（Legend）の非重なり配置**:
  - SVG キャンバス内部の右下／左下に直接描画していた `<g className={styles.mapLegend}>` は、地形・ピンと重なりズーム時に巨大化するため廃止する。
  - 凡例は SVG キャンバス外のツールバー（開閉トグル付きのコンパクト凡例バー）またはマップ下部フッターへ外出しし、地図の視認領域を100%確保する。

### DEC-23：Issue #52〜#64 NFC→BLE設置・基準取得→帰社後PC同期→LoRa継続監視の統合アーキテクチャ（2026-10-29）

NFC/BLE設置登録、圏外持ち帰り、帰社後PC同期、およびLoRa姿勢継続監視の一連のパイプライン（Issue #52〜#64）を以下の統合設計に基づいて実装する。

1. **共通データ契約とID体系（Issue #53）**:
   - `request_id`: 端末の操作・再送単位（UUIDv4）。同一 `request_id` の再送は冪等に同一結果を返し、ペイロードが異なる場合は競合（`409 Conflict`）とする。
   - `installation_id`: 機体の物理設置単位（`inst_<node_id>_<timestamp>` または UUIDv4）。再設置時に新設され、機体およびPC上で過去の設置履歴と分離して管理する。
   - `capture_id`: 静止区間基準サンプリング結果ID（UUIDv4）。機体NVSおよびPC SQLiteに不変レコードとして保存される。
   - `boot_id`: 機体の起動セッション単位（UUIDv4またはブート毎のハッシュ/整数）。再起動しても `installation_id` は維持し、`boot_id` のみを更新する。
   - `sample_seq`: 起動ごとの連続サンプリング番号。
   - **軸・単位・校正版の統一**: 加速度はXYZ 3軸、mg単位（1G ≈ 1000mg）、ADXL367設定版（`config_version = 1`）をBLE基準取得とLoRa観測で完全に一致させる。

2. **ファームウェア仕様（Issue #54, #55）**:
   - ESP32C3上で動作する静止確認状態機械（`IDLE` → `WAIT_STILL` → `SAMPLING` → `COMMITTED` → `REPORTED`）を実装。
   - 全軸ゼロ、飽和、分散過大（揺れ検知）、件数不足を異常として拒否し、静止確定区間（例: 2000ms / 20サンプル）の平均mgおよび分散（品質）をNVSへ原子的に保存する。
   - BLE GATTサービス（標準DeviceInfo、山網設置サービスUUID、設置命令キャラクタリスティック、状態・結果取得キャラクタリスティック）を提供。
   - NFCタグの `node_id` とBLE照合、認可トークンによる不正操作防止、電源投入後一定時間の待受窓（タイマー制御）を実装。

3. **LoRa新パケット形式S1とS0下位互換（Issue #56）**:
   - 新形式 `S1`: `S1,<node_id>,<installation_id>,<boot_id>,<sample_seq>,<hop>,<sample_ms>,<ax_mg>,<ay_mg>,<az_mg>,<soil_raw>,<battery_mv>,<config_version>`（13項目）。
   - 旧形式 `S0`（10項目）と `S1` を自動判別し、パースする。PC未同期の `installation_id` を持つ観測レコードは「未確定設置観測」として一時保持し、同期完了時に確定設置へ自動バインドする。

4. **PWA現場オフライン起動と安全コンテキスト（Issue #38, #58）**:
   - Web App Manifest（`manifest.webmanifest`）および Service Worker（`public/sw.js`）を導入。
   - `/mobile` 画面シェルおよび静的アセットをCache APIで事前キャッシュし、携帯圏外・PC不在の環境でもブラウザ終了後に再起動できるようにする。
   - IndexedDBを端末側永続ストアとして使用し、PCの接続元IP変更に影響されない固定 origin スコープで未同期キューを保護する。

5. **PC冪等同期APIとSQLite永続化（Issue #59）**:
   - バックエンドに `Installation`、`Capture`、`SyncRequestLog`、`AlertEvent` テーブルを追加。
   - `POST /api/v1/installations/confirm` により、位置情報・精度・設置日時・基準XYZ・取得品質を単一トランザクションで確定。
   - `GET /api/v1/installations/status/{request_id}` による同期状態の冪等照会。
   - 旧 `sanmou-test-baseline-state.json` のデータをSQLiteへ自動移行し、二重正本を排除する。

6. **現場未同期キューと帰社後同期（Issue #57, #60）**:
   - Web Bluetooth API による現場BLE接続・基準取得のフロントエンド実装（非対応環境・権限拒否のエラーハンドリング含む）。
   - 取得結果とGPS位置情報をIndexedDBの永続キューへ保存（状態: `prepared` → `device_saved` → `local_saved` → `syncing` → `synced` / `conflict`）。
   - 帰社後、許可済みPC（認証トークン検証）への一括手動同期と応答確認。

7. **PC常駐姿勢変化判定エンジン（Issue #61）**:
   - 重力ベクトル内積による角度差 $\theta = \arccos\left(\frac{\mathbf{v}_{\text{baseline}} \cdot \mathbf{v}_{\text{obs}}}{|\mathbf{v}_{\text{baseline}}| |\mathbf{v}_{\text{obs}}|}\right)$ をPCバックエンド常駐処理で集約計算。
   - ブラウザが閉じられていても、シリアル受信したS1/S0観測から継続判定し、`AlertEvent` をDBへ記録。
   - 警告確認・消音・解除の状態をサーバー側で保持し、基準再設定と明確に分離する。

8. **UI統合表示（Issue #62）**:
   - 地図（`/map`）、管理台帳（`/sensors`）、詳細（`/sensors/[id]`）、スマホ（`/mobile`）で共通の設置ID・基準値・監視状態（未確定、観測待ち、監視中、品質不良、通信途絶）を表示。
   - デモデータと実機データを明瞭に分離し、未受信・未判定を正常と誤表示しない。

9. **実機通し検証とアプリ移行境界（Issue #63, #64）**:
   - 通し試験シナリオ（`docs/VALIDATION.md`）および自動E2E検証スクリプトを作成。
   - BLE / NFC / 位置情報 / ストレージの抽象インターフェースを整備し、Capacitor等のネイティブアプリへ置換可能な境界を保証する。
