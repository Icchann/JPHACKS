# USE_CASES.md — 林業現場ユースケース集・業務シナリオ定義書

> 文書版: 1.0 / 2026-10-24  
> 対象: JPHACKS / 山網（Sanmou）  
> 目的: 林業従事者・森林組合のリアルな業務フローに即したシステム価値と、ソフトウェア・ハードウェア連携シナリオを定義する。

## 1. 林業現場の過酷な実態と開発背景

山林現場（伐採地・造林地・作業道）は、一般的なITツールが想定するオフィス環境とは根本的に異なる以下の制約・リスクを抱えている。

1. **屋外で画面を操作できない（操作不能の原則）**:
   - 急傾斜、足場の悪さ、泥や雨、防振手袋の着用により、山中でPCを開くことは不可能であり、スマホの文字フリック入力も極めて困難かつ滑落リスクを伴う。
   - 「屋外で操作しなくても命を守れること（＝屋内での事前判断 ＋ 緊急時の通知受領）」が本システムの根本理念である。
2. **重機とチェーンソーの騒音**:
   - 80〜100dBを超える騒音下でヘルメット・耳栓を着用しているため、落石音や地鳴りなどの前兆現象を作業員自身の耳で感知することはできない。
3. **電波の完全不通**:
   - 山間深部は携帯キャリアの電波が届かず、一般的なクラウドサービスやAPIは機能しない。
4. **多重の情報が錯綜する山林管理**:
   - 現場にはセンサー値だけでなく、**私有地境界（越境伐採禁止）**、**作業道や獣道（轍）**、**スズメバチやマムシなどの危険生物生息域**、**休憩ポイント（詰所・水場）**、**崩れやすい地質帯**など、作業員の命と権利に関わる多層の情報が存在する。

## 2. 想定ペルソナ（登場人物）

| ペルソナ | 役割 | 主な利用環境 | 主な関心事 |
|---|---|---|---|
| **森林組合 作業班長** | 現場統括・出動判断 | 詰所・事務所 PC / スマホ | 「今日の雨で斜面は崩れないか？どの工区なら作業できるか？」 |
| **現場作業員** | 伐採・搬出・重機オペレーター | 山中現場（スマホのみ所持） | 「作業中に斜面が動いたら即座に知らせてほしい」 |
| **林務・防災管理者** | 組合・自治体での全体監視 | 事務所 PC 大画面 | 「広域の複数山林で異常が発生していないか」 |
| **ハードウェア開発担当** | センサー・LoRa・集約機製作 | ラボ / 現場ノートPC | 「S0パケットが正常に欠損なく受信・可視化されているか」 |

## 3. コア・ユースケース

### ユースケース 1: 朝礼時の出動可否判断（Go / No-Go 判定）
- **アクター**: 森林組合 作業班長、現場作業員全員
- **タイミング**: 毎朝 7:30、作業開始前の詰所・事務所
- **利用デバイス**: 詰所ノートPC（`http://localhost:3000/map`）
- **シナリオ**:
  1. 作業班長が現場詰所のノートPCを開く。
  2. メイン画面のヘッダーに **「全工区 正常稼働中（危険: 0件）」**、または **「警告: 第3工区斜面 S1の土壌水分88%（要注意）」** とサマリーが表示される。
  3. 地図上で該当工区のピンを確認。昨夜の大雨で土壌水分が飽和し、斜面ノードが微小に変位していることを確認。
  4. 班長は朝礼で「今日の第3工区の急斜面伐採は中止し、緩傾斜の第1工区の間伐に切り替える」と即断。
- **効果**: 斜面崩壊・土砂崩れによる重機横転や生き埋め事故を「入山前」に100%未然防止する。

---

### ユースケース 2: 作業中の「逃げろ！」緊急プッシュ通知・メール発火
- **アクター**: 伐採・集材作業中の現場作業員
- **タイミング**: 山中での作業中（突発的な地すべり・斜面変位発生時）
- **利用デバイス**: 胸ポケットのスマートフォン（バイブレーション ＋ アラート音）
- **シナリオ**:
  1. 作業員は重機オペレーションやチェーンソー作業を行っている（画面は見ない）。
  2. 集中豪雨や地盤緩みにより、斜面ノード（`S1`）の加速度が急変し、傾斜角が連続してしきい値を超過。
  3. 詰所PC（または中継器）が異常を即座に判定し、作業員のスマホへ **Web Push通知** または **緊急メール** を自動発火。
  4. 作業員の胸ポケットでスマホが激しく連続振動し、大音量のアラート音が鳴動。
  5. 作業員は作業を即座に中断し、安全退避ルート（作業道）を通って緊急避難。
- **効果**: 騒音と作業集中で前兆に気づけない作業員へダイレクトに危険を伝え、命を守る。

### ユースケース 3: NFCタグによる「かざすだけ」のセンサー情報固定
- **アクター**: センサー設置・定期点検を行う作業員
- **タイミング**: 山林への新規センサー設置時、またはバッテリー交換・点検時
- **利用デバイス**: スマートフォン（Web NFC対応ブラウザ / PWA）
- **シナリオ**:
  1. 作業員は斜面の杭または立木にセンサー筐体を打ち込み固定する。
  2. センサー筐体に埋め込まれた **NFCタグ** にスマホを「ピッ」とかざす。
  3. スマホの「山網」アプリが起動し、タグから「ノードID: `S1`」を読み取る。
  4. 同時にスマホ内蔵のGPSから設置緯度・経度を取得し、**スマホの高精度時計から設置日時（タイムスタンプ）を自動取得**する（※センサー端末内には時計RTCが非搭載のため、スマホ側で時刻を確定付与して補完する）。
  5. 画面に「S1（斜面ノード）を現在地・現在時刻で登録しますか？ [登録]」と表示され、作業員はワンタップ。
  6. 登録データは電波ゼロの現場でもスマホ端末内メモリ（ローカル）に「未同期データ」として安全に蓄積される。
  7. 作業終了後、会社・事務所に戻り会社WAN（Wi-Fi）に接続された瞬間に、PCのFastAPIへ一括送信され、PC側のSQLite台帳へ自動同期される。
- **効果**: センサーの時計非搭載というハードウェアコスト制約をスマホ側で解決し、過酷な山中でのキーボード手入力を完全排除して、打ち間違いと同期漏れを撲滅。

### ユースケース 4: 樹木ノード（T）と斜面ノード（S）の直感的なリスク識別
- **アクター**: 監視者、林道管理者
- **タイミング**: 地図画面（PC）の閲覧時
- **利用デバイス**: PC画面
- **シナリオ**:
  1. 地図上に配置されたアイコンを見るだけで、リスクの性質を即座に識別可能。
     - **🌲 樹木ノード（T）**: 風倒木、根返り、集材架線（ワイヤー）過負荷による倒木リスク。
     - **⛰️ 斜面ノード（S）**: 表層崩壊、地滑り、土砂流出、作業道法面の崩落リスク。
  2. 強風時には樹木ノード（T）が一時的に大きく揺れるが、周期的な揺動は風とみなし誤警報を抑止。一方、斜面ノード（S）が恒久的に傾いた場合は即時「危険」と判定。
- **効果**: 単なる「傾き」ではなく、林業の実態に即した誤報のない正確なリスク判断を実現。

---

### ユースケース 5: 多層マップレイヤー切り替え（情報過多の解消と現場最適化）
- **アクター**: 森林組合 現場班長、作業道プランナー
- **タイミング**: 作業前ミーティング、パトロール計画策定時
- **利用デバイス**: PC画面
- **シナリオ**:
  1. マップ上には膨大な情報が存在するが、すべてを常時表示すると画面が埋め尽くされ、最も重要な「センサーの危険色」が見落とされる。
  2. 画面上部の **「レイヤー切替ボタン」** または **「透過度スライダー」** により、用途に応じて瞬時に表示を切り替える。
     - **【災害警戒モード（デフォルト）】**: センサーピンと危険地すべり斜面のみを高輝度表示。他情報は非表示。
     - **【作業・動線モード】**: 「休憩ポイント（詰所・水場）」「作業道の轍（重機通行可能ルート）」「獣道」をハイライト。
     - **【境界・土地管理モード】**: 「私有地境界（赤線）」「保安林指定区域」を表示し、誤伐・越境伐採を防止。
     - **【環境・安全注意モード】**: 「スズメバチ営巣地」「マムシ多発沢」「落石多発地点」を表示。使わない時は「薄く（30%透過）」または「非表示」にワンクリック切り替え。
- **効果**: 現場の利用目的に応じて地図を最適化し、認知負荷を激減させつつ、安全管理・土地境界トラブルを同時に防止する。

### ユースケース 6: 危機的状況における近接SOSヘルプ発信（現場ピアツーピア救助）
- **アクター**: 斜面崩壊、滑落、倒木挟まれ、体調急変などの危機的状況に遭遇した作業員
- **タイミング**: 山中現場で緊急救助が必要な瞬間
- **利用デバイス**: スマートフォン（山網アプリ）
- **シナリオ**:
  1. 作業員が滑落や負傷により身動きが取れなくなる。
  2. 携帯キャリアの電波が圏外であっても、山網アプリの「🆘 緊急ヘルプ」ボタンをタップ（またはシェイク操作）。
  3. アプリが近接無線（BLE / Wi-Fi Direct）で半径数十メートル〜百メートルの周囲に向けてSOSビーコン信号を緊急発信。
  4. 付近で作業している仲間のスマホの山網アプリが信号を検知し、大音量アラートとバイブレーションで「⚠️ 付近の作業員から救助要請を検知！」と通知。
  5. 仲間が即座に現場へ駆けつけ、初期救助活動へ移る。
- **効果**: キャリア電波が一切届かない山林深部でも、近接通信を活用して孤立死や救助遅れを防ぐ。

## 4. チーム開発（ハードウェア協調）におけるシナリオ

- **ハードウェア担当者とのインターフェース**:
  - ハードウェアチームが製作する集約機からは、`S0,node_id,seq,hop,sample_ms,ax_mg,ay_mg,az_mg,soil_raw,battery_mv` という明確に規定されたCSVレコードがUSBシリアル経由で届く。
  - ソフトウェア側は、ハードウェアのテスト中であっても、起動ログの混入や不正パケットでクラッシュしない頑健な受信パイプライン（`InvalidSerialRecord` 統計処理）を提供し、ハードウェアチームが単体デバッグを行いやすい環境を保証する。
- **NFCタグ規格**:
  - NDEF形式で `node_id`（例: `"S1"`）および固定公開鍵/MACアドレスを保持する安価なNTAG213/215系を想定。
